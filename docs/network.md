# 5GHz Wi-Fiと保護方針

PiがAPになる場合も、Pi/C5が外部ルーターのSTAになる場合も、IPv4到達性を準備すれば同じUDPパケットを使います。ルーティング設定とアプリケーションを分離します。Pi型番・C5ボード・国/チャネルが未確定なのでAP作成コマンドや固定IPは実機値として確定しません。

## 接続前に確認すること

1. Pi無線チップの5GHz/AP対応とOSの管理方式を確認する。
2. 国内利用条件と会場指定の帯域/チャネルを確認する。DFSやAP isolationの影響も測定する。
3. 専用ネットワークでIPとUDP portを明示し、送信元IP/portを受信側へ登録する。Piは `--source-port` で固定可能。
4. パケット遅延・欠落・混雑時挙動をモーター電源なしで測定する。
5. 50Hz/180msを出発点として、受信周期・制御周期・実停止時間から期限を決定する。

現状はPi側UDP送信、C5側ノンブロッキングUDP socketアダプターと送信元照合を実装しています。app_mainはソケットもWi-Fiも開始しません。`WifiStation` は5GHz限定STA接続と切断/取得IPフラグを実装していますが、app_mainと安全制御タスクへの接続は未実装です。PiのAPモードでも外部ルーターでもC5はSTAとして動作します。

## 認証と保護

- Wi-Fiは機器が対応するWPA2/WPA3の専用資格情報を使用し、共有公開SSIDやインターネット越しに操縦ポートを公開しない。
- OS/ルーターで送信元制限を行う。受信クラスも送信元IPv4とportを照合する。
- IP/port制限はなりすまし防止には不十分。UDP v1は暗号学的認証・改ざん検出・新規セッションnonceを持たないため**隔離ベンチ専用**。
- 実機運転へ移る前に、事前共有鍵によるMACまたは検証済みの認証付き輸送、チャレンジnonce/セッションID、受信期限とリプレイ対策を追加する。独自暗号を発明しない。
- 秘密情報はOS、ローカル設定または私有ESP-IDF設定で管理する。`config.local.*`、`secrets.*`、`sdkconfig` はignore対象。CIログへ資格情報を出さない。
- 通信再開やIP取得イベントでARMしない。物理許可・ニュートラル・明示ARMを独立して確認する。

受信ソケットは1pollにつき最大8 datagramとし、入力洪水で安全tickが停止しない構造です。送信元違反は無視し、登録済み送信元の長さ/内容不正はFAULT、古いsequenceもFAULTです。無効入力は期限を更新しません。

## 再起動と再接続

送信側が再起動してsequenceが戻っても、受信側は無条件に順序基準を消去しません。v1のベンチ再開は出力を無効化し受信器を再生成してからDISARM→ARM。将来の実運用は認証された新規セッション開始で安全に基準を更新します。再起動直後のDRV無効は維持します。

## ログ・ゲイン調整チャネル（サービスパケット）

`sakura-tune`（Pi）が走行と同じ信頼済み送信元IP/portからESP32へ要求し、ESP32が同じ宛先へ返信します。このため`--source-port`はESP32側の送信元portと一致させます。同じportを使うので`sakura-tune`と`sakura-pilot`は同時に起動できません。操縦しながら使う場合は`sakura-pilot --host … --console`で、標準入力から同じ`monitor` / `param`コマンドを実行します（1ソケットを共有。monitor実行中のparamは拒否、`stop`でmonitorを止める）。形式は[仕様](../protocol/specification.md)を参照。

- ESP32は要求時（LOG_START）にだけ送信し、lease切れで止めます。送信はノンブロッキングで、失敗時は破棄して制御周期を遅らせません。
- ゲイン変更はDISARM時のみ。ARM/DRIVE中は拒否されます。
- **この経路は認証されていません。** 同一セグメントの機器が信頼済みIP/portを騙れば、DISARM中のゲインを変更できます。実機駆動前に認証を整備してください。
